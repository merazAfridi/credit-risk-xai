# Credit Risk Analysis & Decision Making Using Explainable AI

A loan approval model with per-decision explanations and a fairness audit across demographic groups.

Given an applicant's age, income, credit score, loan amount, and gender, the app returns an approve/deny decision, the model's raw confidence, and a plain language breakdown of the reasons. The reasons are restricted to legitimate credit factors; protected attributes (race, gender, disability, etc.) are excluded from the explanation, even though they are accounted for in the fairness pass.

## Run locally

```bash
pip install -r requirements.txt
python app.py
```

Requires `fair_loan_model.joblib`, `model_columns.joblib`, and `template_row.joblib` (included). These are generated by running `credit-risk.ipynb` end to end through Section 9.

## Model comparison

Six algorithms were trained on 7,500 applicant records and compared on held out test data:

| Model                   | Accuracy   | AUC-ROC    |
|--------------------------|-----------|-----------|
| **LightGBM**             | **0.6302**| 0.6492    |
| CatBoost                 | 0.6280    | 0.6672    |
| Logistic Regression      | 0.6276    | **0.6737**|
| Random Forest            | 0.6244    | 0.6578    |
| XGBoost                  | 0.6187    | 0.6515    |
| HistGradient Boosting    | 0.6160    | 0.6468    |

All six land in the same 62 to 67% range, which points to a data ceiling rather than a modeling gap. LightGBM was chosen for deployment for its accuracy and its native support for feature attributions.

## Explainability (SHAP)

- Global: `Credit_Score` and `Income` are the dominant drivers of the model's decisions.
- Local: per-applicant waterfall breakdowns feed the "Why this decision" panel in the app.
- The app computes these via LightGBM's native `pred_contrib`, which gives SHAP equivalent per-feature attributions without an extra dependency.

## Fairness audit and mitigation

Audited across `Gender` with [Fairlearn](https://fairlearn.org/):

| Metric                          | Baseline (LightGBM) | After `ThresholdOptimizer` |
|----------------------------------|---------------------|------------------------------|
| Demographic Parity Difference    | 0.1102              | **0.0074**                  |
| Equalized Odds Difference        | 0.1012              | **0.0276**                  |
| Overall Accuracy                 | 0.6302               | 0.6240                      |

The baseline model showed a gap of more than 10% in approval rates across gender. Applying Fairlearn's `ThresholdOptimizer` (post-processing, `demographic_parity` constraint) closes both fairness gaps by roughly 90%, at a cost of 0.6 points of accuracy. The deployed app runs this mitigated pipeline, not the raw model.

